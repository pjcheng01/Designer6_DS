## 五、解決的問題，分五類

**1. 編碼（本專案最大的雷）**
`.lsp` 要 UTF-8、`.dcl`/`.ini`/`.doc`/`.dat` 要 cp950、`.ps1` 要 UTF-8 with BOM。
早期一次用 `errors='replace'` 的批次轉換在 6 個檔案裡留下約 11,953 個 U+FFFD，
中文永久損毀。教訓寫在手冊第 3 章：**不要整批重跑編碼轉換**。

**2. 無聲失敗**
19 處頂層 `(defun *error* (msg) (princ))` 會永久換掉全域 `*error*`，
導致整個工作階段的錯誤訊息全被吞掉。這是排查效率最大的殺手（§5.16）。

**3. DraftSight 與 AutoCAD 的行為差異**
38 個小節，全部是實測得出、不是文件抄來的。影響最廣的幾個：
`strcase` 逐位元組會改壞 Big5（§5.33）、`read-line` 不吐檔尾空行（§5.2）、
DCL 的 `label` 值不加引號整檔載不起來（§5.24）、
`-LAYER` 不接受目前圖層也不接受空項目而且失敗時指令不結束（§5.36）。

**4. 原版就存在的舊缺陷**
`HRINGS1` 呼叫錯函式、`curltyle` 拼錯、`str_merge` 產生結尾與重複逗號等。
這些在 AutoCAD 下被容忍，換到 DraftSight 才爆出來。

**5. 移植過程自己造成的迴歸**
最典型的是批次補 `unload_dialog` 造成 20 處重複，按「取消」會讓 DraftSight
崩潰（§5.31）。**批次修改一定要回頭驗**，這條寫進了手冊。

## 六、刻意不做的事，與理由

| 事項 | 決定 |
|------|------|
| `a0c0ec6` 與 `docs\瘦身分析-PDM與外部程式.md` 的明文 Oracle 密碼 | **不處理**。repo 為 private，對外一律走 release，而 `build_release.ps1` 有專項檢查會擋下含密碼的交付內容 |
| `.lsp` 加密／保護 | **不做**。調查結論：DraftSight 沒有 Visual LISP 執行期（`.vlx`、`vl-load` 在 195 個 exe/dll 裡完全不存在）；AutoCAD PROTECT 格式本質是可逆變換，本專案自己就用下載來的工具在一天內解開過兩支（`decrypt_lisp_batch.ps1`）。散布對象是公司內部同仁，成本高於收益 |
| 移除程式中的「凱柏」字樣 | **取消**。統計結果：程式碼只有 `PDMBOM3.LSP` 2 處（註解與訊息）；`shscal.ini` 那 2 處是「圖紙型式」下拉選項的**段名**，刪掉會讓「放圖框定比例」整個不能用，只能改名；其餘 145 處都是料號資料 |
| `oerr` 不是區域變數（§5.16 末） | **維持現狀**。17 個安裝點已逐一確認彼此不互相呼叫，不會互相覆蓋。日後若新增巢狀呼叫才需處理 |

## 七、日後維護的五條鐵律

1. **改任何 `.lsp` 之前先看原版**（`C:\DESIGNER6` / `C:\POWPARTS`）。多數「移植版壞掉」
   的問題都能靠 diff 原版快速定位。
2. **動手前先驗編碼**，不要憑檔名或印象猜。絕不可在單一檔案內混用編碼。
3. **不要用 `sed -i` 改 CRLF 檔**。這個環境的 `sed`／`awk`／`grep` 都是文字模式，
   會吃掉 `\r`，而 `grep -c $'\r'` 驗不出來（§5.38）。
4. **括號檢查要跳過字串與註解**（§5.37），而且它不認得 `;| … |;` 區塊註解（§5.20）。
5. **改完請使用者在 DraftSight 實測，通過才 commit。** 這個環境無法自動化測試，
   所有「已修復」都只能是「已修改，待驗證」。

## 八、發布機制

```
（料號資料若有更新，先 xml2partdata.py → commit）
        ↓
git tag release-<日期>
        ↓
powershell -ExecutionPolicy Bypass -File tools\build_release.ps1
```

`build_release.ps1` 用 `git checkout-index` 從 `HEAD` 匯出，所以**工作區不乾淨就會中止**，
交付內容保證等於某個 commit。目錄的預設方向是相反的，新增檔案時要注意：

- `docs\` **預設不交付**——新增任何檔案自動被擋
- `安裝說明\` **預設會交付**——只放寫給收件者看的東西

細節見手冊 §9.7。
