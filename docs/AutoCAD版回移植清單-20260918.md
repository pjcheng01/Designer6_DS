# A 類：AutoCAD 下也是錯的

## A-1　`c:HRINGS1` 呼叫錯函式

**位置**：`C:\DESIGNER6\COMMAND.lsp:62`

```lisp
62 (defun c:HRINGS1() … (cond ((null userblkm)(load "userblkm"))…) (userblku "userblkm" "userblkm" "HRINGS" "poweriso" 0))
63 (defun c:HRINGS2() … (cond ((null userblku)(load "userblku"))…) (userblku "userblku" "userblku" "HRINGS" "poweriso" 0))
```

**成因**：第 63 行（HRINGS2）載入 `userblku`、呼叫 `userblku`，前後一致。
第 62 行是複製它改的，`(load …)` 那半改成了 `userblkm`，**呼叫那半忘了改**。
傳入的 DCL 檔名與對話框名也都是 `"userblkm"`，可見原意就是 `userblkm`。

**後果**：
- 若該工作階段先用過 HRINGS2，`userblku` 已定義 → 用**錯誤的處理函式**配
  `userblkm` 的對話框
- 若沒用過 → `no function definition: USERBLKU`

**修法**：`(userblku …)` → `(userblkm …)`，一個字。

## A-2　`curltyle` 拼錯（5 處）

**位置**：`ASSEMBLY.lsp:232`、`MANABLK.lsp:422`、`MANAPART.lsp:2213 / 2416 / 2450`

**成因**：存線型時用 `(setq curltype (getvar "celtype"))`，還原時打成 `curltyle`。
全庫 `curltype` 用了 **44 次**、`curltyle` **5 次**——比例本身就是證據。

**後果**：`curltyle` 是未定義變數（nil），於是變成
`(command "linetype" "s" nil "")`，**線型還原失敗**。

**修法**：5 處全部改成 `curltype`。

> DraftSight 版只改了 4 處，因為 `MANABLK.lsp` 在瘦身階段已移除。
> **AutoCAD 版要改 5 處。**

## A-3　`c:outbom_out` 從來沒有定義過

第一次使用、設定檔還沒建立時就會踩到。

**修法**：確認原意後，刪掉呼叫或補上實作。

## A-4　`SCREW1.LSP` 拿 `t` 當變數（2 支還沒修）

**位置**：`C:\POWPARTS\SCREW1.LSP`

**這一項有原作者留下的歷史證據**：

```lisp
54          ~t (polar p5 (+ (- (/ pi 3)) ang) (- (/ b 2) d1))    ;-----2003.02.24 SAM-----
55         ;t (polar p5 (+ (- (/ pi 3)) ang) (- (/ b 2) d1))
```

2003-02-24 由 SAM 把 `t` 改名成 `~t`，連同兩處使用一起改（75、78 行）。
**但只改了 `jabase_S` 一支**，另外兩處（141、227 行）到今天還是 `t`。

| 指令 | 函式 | 用 `t` 嗎 | 狀況 |
|------|------|----------|------|
| `&JAbase` | `jabase_S` | 2003 已改 `~t` | 正常 |
| `&Lbase` | `lbase_S` | 沒用到 | 正常 |
| `&Jbase` | `jbase_S` | **用了** | **有問題** |
| `&LAbase` | `labase_S` | **用了** | **有問題** |

**後果**：`(setq t …)` 覆寫 LISP 常數 `T`。**2003 年原作者就是因為出問題才改的**
——這是本清單裡唯一有歷史實證的一項。

**修法**：比照 `~t` 的命名，連同使用處一起改。

## A-5　`*error*` 的三個層次 ★ 影響最大，建議第一個修

這不是單一 bug，是三個疊在一起，結果是**整個 AutoCAD 工作階段的錯誤訊息
全部被吞掉**。移植初期為了這件事繞了十幾輪才找到。

### (a) 頂層的 `(defun *error* (msg) (princ))` — 19 處

```lisp
(defun *error* (msg)
   (princ)
)
```

**它不在任何函式裡**，是頂層運算式——檔案一被 `load` 就永久換掉全域
`*error*`，而且沒有任何地方會還原。`MANAPART` 與 `DFSYSTEM` 幾乎每個功能
都會載入，所以**開機用過一兩個指令之後，這個 session 就再也看不到錯誤訊息**。

### (b) `(if oerr (setq *error* oerr))` — 33 處

`oerr` 為 nil（代表原本是預設處理器）時**不還原**。而
`(setq oerr *error* *error* my_err)` 在 `*error*` 還是預設值時，`oerr` 就是 nil。

**修法**：改成無條件 `(setq *error* oerr)`——設成 nil 本來就代表「還原成內建處理器」。

分布（原版實測）：`C:\DESIGNER6` 8 處（`AUXDIM.lsp` 5、`AUXDRAW1.lsp`、
`MANAPART.lsp`、`SHSCAL.lsp` 各 1）；`C:\POWPARTS` 25 處（`5-1`～`5-7` 各 1、
`SCREW.LSP` 與 `STEEL.LSP` 各 2、其餘各 1）。

> DraftSight 版的 commit `55bc60f` 寫的是「9 個」，跟這裡的 33 不符——因為
> 移植版瘦身時移除了一批檔案，而 `POWPARTS_DS` 是另一個 repo。**以本清單的
> 33 處為準**，那是直接在原版兩棵樹上數的。

### (c) 正常結束時不還原 — 17 個安裝點

處理器裡的還原只有「真的出錯」才跑得到；**沒出錯的那條路徑跑完，`*error*`
仍停在自訂處理器上**。

**盤點時的陷阱**：有三個是分兩行寫的，只比對單行的
`(setq oerr *error* *error* X)` 會漏掉：

```lisp
(setq olderr *error*
      *error* at_err)
```

**修法與完整檔案清單**見 DraftSight 版手冊 §5.16，三層都有對應處理。

> **後續注意**：`oerr` 在這些函式裡都不是區域變數（沒列在 `/` 後面），是全域的。
> 目前的安裝點彼此不互相呼叫所以沒事；日後若新增巢狀呼叫，內層結束時會把
> `*error*` 還原成外層的處理器而不是內建處理器。要根治就把 `oerr` 加進各自的
> 區域變數表。

## A-6　`S_ASMSET.lsp`：答 N 時沒有載入 `manapart`

**位置**：`C:\DESIGNER6\S_ASMSET.lsp` 的 6 個進入點（`c:subsys`、`c:part_cr`、
`c:part_DEL`、`c:Sub_REmove`、`c:Sub_On_Off`、`c:Sub_Reverse`），
`(load "manapart")` 在 63、83、687、708… 行。

**成因**：`(load "manapart")` **只寫在「答 Y 自動建立資訊點」的分支裡**。

```lisp
(if (or (= (strcase len_blance) "Y") (= (strcase len_blance) "YES"))
    (progn
         (load "manapart")        ; ← 只有答 Y 才載入
         (c:automakepart)
         …
    )
)
```

**後果**：答 N → `manapart` 沒載入 → 選完零件按 Enter 時
`subsys_ok&fun1` 呼叫 `addatt_tobomball`（定義在 `MANAPART.lsp`）→ **無函數**。

**同一套原版自己就有正確寫法**可以照抄——`ASSEMBLY.lsp:85` 與 `213`：

```lisp
(if (or (null get_bomdata)(null addatt_tobomball))(load "manapart"))
```

`S_ASMSET.lsp` 裡這種守衛是 **0 處**。

**修法**：在每個進入點無條件加上 `ASSEMBLY.lsp` 那一行。

## A-7　`layeroff&*`：目前圖層的比對永遠漏掉每批最後一個

**位置**：`C:\DESIGNER6\S_ASMSET.lsp:567` 等 **6 處**（`&fun1`、`&part_cr`、
`&part_DEL`、`&Sub_REmove`、`&Sub_On_Off`、`&Sub_Reverse` 各一份）

```lisp
(defun layeroff&fun1(en)
     (setq en (strcat "," en))
     (if (/= (string_search&fun1 (strcase en) (strcat ","(getvar "clayer") ",") ) nil)
         (command "-layer" "off" en "y" "")
         (command "-layer" "off" en ""))
);defun
```

`en` 是逗號合併的圖層清單（`"LAY1,LAY2,LAY3"`），上一行前置一個逗號。
比對的目的是「這批裡有沒有目前圖層」，有的話要補 `"y"` 回答 AutoCAD 的
「確定要關閉目前圖層嗎」。

**兩個缺陷**：

1. **`en` 前面補了逗號，結尾沒有。** 要找的是 `",CLAYER,"`，但 `en` 是
   `",LAY1,LAY2"`——**每批的最後一個圖層永遠比不中**。
2. **`(strcase en)` 轉了大寫，`(getvar "clayer")` 沒轉。** 大小寫不同就比不中。

**後果**：該補 `"y"` 的時候沒補 → `-LAYER` 跳出確認提示，程式送的 `""` 被當成
預設答案 → **目前圖層沒有關掉**，而且可能多吃掉一個輸入。

**修法**：比對時兩邊都包前後逗號、兩邊都 `strcase`：

```lisp
(string_search&fun1 (strcase (strcat "," en ","))
                    (strcase (strcat "," (getvar "clayer") ",")))
```

> DraftSight 版的做法不同——那邊**根本關不掉目前圖層**，所以改成送出前先把
> 目前圖層從清單濾掉。AutoCAD 不需要那樣做，**補好比對、保留 `"y"` 就對了**。

# B 類：AutoCAD 容忍，回移植屬加固

## B-1　`chg_dim_ok` 的防護寫在解參照之後

**位置**：`C:\DESIGNER6\AUXDIM.lsp:885-889`

```lisp
(setq up_dim (entsel "\n選取欲變更之尺寸"))
(setq updim_data (entget (car up_dim)))   ; ← 按 Enter 時 up_dim 是 nil
(setq olddim (assoc 1 updim_data))
(if up_dim                                 ; ← 防護在這裡，太晚了
```

防護存在，但前面兩行已經先解參照了。**AutoCAD 的 `(entget (car nil))` 回 nil
不報錯**，所以完全看不出來；DraftSight 才會炸。

`c:chg_dim` 的設計本來就是「按 Enter 結束迴圈」，所以這是**正常用法**。

**修法**：兩行移進 `(if up_dim …)` 的成立分支，包一個 `progn`。
AutoCAD 下沒有可見收益，純粹是正確性。

> **值得記住的排查規則**：看到 `(if X …)` 這種防護，要往**上**檢查——
> `X` 在被判斷之前有沒有先被解參照過。

## B-2　`str_merge&*` 產生結尾逗號與連續逗號

**位置**：`C:\DESIGNER6\S_ASMSET.lsp` **6 處**

```lisp
(if (<= (strlen (setq mergedata (strcat merge_str  "," str ","))) 240)
```

逐次展開：

| 第幾次 | 產生的字串 |
|---|---|
| 1 | `"LAY1"` |
| 2 | `"LAY1,LAY2,"` ← 結尾逗號 |
| 3 | `"LAY1,LAY2,,LAY3,"` ← 雙逗號 + 結尾逗號 |

**AutoCAD 的 `-LAYER` 容忍這種字串**；DraftSight 會回「找不到相符的圖層名稱。」
而且指令不結束。

**修法**：去掉結尾那個逗號 → `(strcat merge_str "," str)`。
AutoCAD 下無可見差異，但配合 A-7 一起改，那段邏輯會乾淨很多。

# C 類：不要回移植

列出來是為了**避免看到 DraftSight 版的 diff 就照抄**。以下全部是 DraftSight
的行為差異，AutoCAD 沒有這些問題，改了只是徒增風險：

| DraftSight 版的修改 | AutoCAD 的情況 |
|---|---|
| `ASCTEXT.lsp` 的 `(setq MLST '` 換行 `())` 改成 `nil` | AutoCAD 讀取器接受 `'` 後換行 |
| `strcase` 全面換成 `strcase_ascii` | AutoCAD 的 `strcase` 不會破壞 Big5 |
| `read-line` 檔尾多一次 nil 檢查 | AutoCAD 會吐檔尾空行 |
| DCL 的 `label` 值補引號 | AutoCAD 不加引號也能載入 |
| `c:` 函式補 `(princ)` 收尾 | AutoCAD 不會把回傳值印在指令列 |
| `-LAYER` 濾掉目前圖層 | AutoCAD 補 `"y"` 就能關（見 A-7） |
| `FILEDIA` / `CMDDIA` 的處理 | 語意在兩邊相反 |
| 拆開的 `(command …)` 合併 | AutoCAD 接得上進行中的指令 |
| `-toolbar` 相關的選單改動 | AutoCAD 有 `-TOOLBAR` |

完整的行為差異清單（38 節）見 DraftSight 版 `docs\移植專案交接手冊.md` 第 5 章。
