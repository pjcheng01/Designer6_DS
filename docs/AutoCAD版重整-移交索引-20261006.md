## 三個最容易踩的坑

**一、刪加密狗外殼會連帶刪掉 `(setq ppss sspp)`。**
那個 `setq` 寫在 `WHILE` 的開頭，刪掉外殼就變未繫結，而算式裡還留著 `ppss`，
`(+ 數字 nil)` 會讓指令中斷。DraftSight 版真的發生過，而且症狀很有誤導性——
畫面先出現「找到 1」才中斷，看起來像選取有問題。詳見任務一文件 §0。

**二、不要直接拿 DraftSight 版的 diff 去套。**
那裡面有一堆 DraftSight 專用的修改（`strcase_ascii`、DCL 補引號、`read-line`
檔尾…），在 AutoCAD 下不但沒必要還可能改壞。任務二文件的 **C 類**就是專門
列這些的。

**三、引用手冊裡的數字前，先回原版數一次。**
手冊的數字多半是**移植版**的，而移植版做過瘦身。例如 `(setq ppss sspp)`
手冊寫 15 處，原版實際有 **138 處**。兩份交接文件的數字都已經重新數過。

## 編碼：原版是 Big5，不要轉

`C:\DESIGNER6` / `C:\POWPARTS` 的 `.lsp` 是 **cp950**，AutoCAD 版**沒有理由轉 UTF-8**。

- 絕不可在單一檔案內混用編碼，寫中文註解前先確認該檔編碼
- **不要整批重跑編碼轉換**——DraftSight 移植早期一次用 `errors='replace'` 的
  批次轉換，在 6 個檔案裡留下約 11,953 個 U+FFFD，中文永久損毀

```bash
python -c "d=open('AUXDIM.lsp','rb').read(); d.decode('cp950'); print('cp950 OK')"
```

# 在新電腦上怎麼開始

## 步驟 0：離開舊機器之前

**把所有 commit 推上去**，否則新機器 clone 不到這些文件：

```bash
cd C:\DESIGNER6_DS && git push origin main
cd C:\POWPARTS_DS  && git push origin main
```

確認推上去了（直接向 GitHub 查，不要只看本地）：

```bash
git ls-remote origin main
```

輸出的雜湊要跟 `git rev-parse HEAD` 相同。

## 步驟 1：搬運

| 來源 | 大小 | 怎麼搬 |
|------|------|--------|
| `C:\DESIGNER6` | 83 MB | **只能實體複製**（無版控） |
| `C:\POWPARTS` | 60 MB | **只能實體複製**（無版控） |
| `C:\DESIGNER6_DS` | 132 MB | `git clone`（也可以複製） |
| `C:\POWPARTS_DS` | 84 MB | `git clone` |

兩棵原版合計 143 MB，隨身碟就夠。**原版沒有版控，弄丟就沒有對照組了**，
複製完先核對檔案數再拔隨身碟。

## 步驟 2：新機器的 git 設定

```bash
git config --global user.name  "PJ"
git config --global user.email "peijie.cheng@gmail.com"
```

clone 移植版的兩個 repo（它們的歷史是用 `autocrlf=true` 提交的）：

```bash
git -c core.autocrlf=true clone https://github.com/pjcheng01/Designer6_DS.git C:\DESIGNER6_DS
git -c core.autocrlf=true clone https://github.com/pjcheng01/POWPARTS_DS.git  C:\POWPARTS_DS
```

> 設錯會讓 `git status` 一次冒出上百個「已修改」的檔案。看到那個現象先懷疑這一項。

## 步驟 3：把 AutoCAD 原版納入版控

這是整份交接裡**最划算的一步**。沒有版控，改壞了很難知道是哪一步。

```bash
cd C:\DESIGNER6
git init
git config core.autocrlf false        # ← 注意，跟移植版相反
git add -A
git commit -m "原版 C:\DESIGNER6，未修改"
```

`C:\POWPARTS` 同樣處理。

> ⚠ **這裡要用 `core.autocrlf=false`，跟移植版不一樣。**
> 這個 repo 的用途是「忠實保存未修改的原版」，不做任何正規化，
> 存進去與取出來都是原始位元組。移植版設 `true` 是因為它的歷史本來就是那樣提交的。
>
> （順帶一提：Big5 的第二位元組範圍是 `0x40–0x7E` 與 `0xA1–0xFE`，不含 `0x0D`，
> 所以換行轉換不會破壞中文。但存檔用的 repo 不做轉換還是比較乾淨。）

建議的 `.gitignore`（擋執行期產物）：

```
Thumbs.db
*.dwl
*.dwl2
*.sv$
*.ac$
*.err
*.bak
~$*
campro.txt
CamproBom.txt
```

## 步驟 4：開 AutoCAD，先量現況再動手

**第一件要確認的事**——加密狗的授權變數到底有沒有值：

```lisp
(princ jin)        ; 預期 "#$%"
(princ ####)       ; 預期 85
(princ sspp)       ; 預期 0
```

這三個結果會決定整個作業的性質：

| 結果 | 代表 | 怎麼做 |
|------|------|--------|
| **都有值** | 授權檢查通過中，334 處外殼裡的程式碼正常執行 | 照加密狗文件 §2 做 |
| **都是 nil** | 檢查一直是失敗的，**那些功能可能從來沒跑過** | **先停下來**，回頭確認那些功能現在能不能用，再談移除 |

接著記錄「修改前」的行為當基準，至少跑這幾支（它們是拆外殼後最可能壞的）：

```
&e-len              線段公英制長度
&pul &pur &pdl &pdr 旋轉投影線
SLOT5               指令列直接打（先跑過 &lc 讓 drawmech 載入）
```
