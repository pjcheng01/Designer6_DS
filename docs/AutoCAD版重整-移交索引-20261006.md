## 三個最容易踩的坑

**一、刪加密狗外殼會連帶刪掉 `(setq ppss sspp)`。**
那個 `setq` 寫在 `WHILE` 的開頭，刪掉外殼就變未繫結，而算式裡還留著 `ppss`，
`(+ 數字 nil)` 會讓指令中斷。DraftSight 版真的發生過，而且症狀很有誤導性——
畫面先出現「找到 1」才中斷，看起來像選取有問題。詳見任務一文件 §0。

**二、不要直接拿 DraftSight 版的 diff 去套。**
那裡面有一堆 DraftSight 專用的修改（`strcase_ascii`、DCL 補引號、`read-line`
檔尾…），在 AutoCAD 下不但沒必要還可能改壞。任務二文件的 **C 類**就是專門
列這些的。

**三、引用手冊裡的數字前，先回原版數一次。**
手冊的數字多半是**移植版**的，而移植版做過瘦身。例如 `(setq ppss sspp)`
手冊寫 15 處，原版實際有 **138 處**。兩份交接文件的數字都已經重新數過。

## 編碼：原版是 Big5，不要轉

`C:\DESIGNER6` / `C:\POWPARTS` 的 `.lsp` 是 **cp950**，AutoCAD 版**沒有理由轉 UTF-8**。

- 絕不可在單一檔案內混用編碼，寫中文註解前先確認該檔編碼
- **不要整批重跑編碼轉換**——DraftSight 移植早期一次用 `errors='replace'` 的
  批次轉換，在 6 個檔案裡留下約 11,953 個 U+FFFD，中文永久損毀

```bash
python -c "d=open('AUXDIM.lsp','rb').read(); d.decode('cp950'); print('cp950 OK')"
```
