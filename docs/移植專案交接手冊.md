## 0. 給接手者的三分鐘版本

- 這是把一套跑了二十多年的 AutoCAD LISP 機械設計外掛（藝祥「機械設計家」Designer6 + POWERPARTS），
  移植到 **DraftSight** 的專案。程式碼是 AutoLISP + DCL，資料是 INI/DAT/DWG/SLD。
- 兩個資料夾、兩套程式：`C:\DESIGNER6_DS`（主系統）與 `C:\POWPARTS_DS`（零件庫）。
  對照組原版留在 `C:\DESIGNER6` 與 `C:\POWPARTS`，**不要動它們**——那是唯一的比對基準。
- 移植的主體工作（去加密狗、去 PDM、編碼轉換、載入鏈、選單）**已經做完**，
  現在是逐一功能實測與修 bug 的階段。
- 這個專案**沒有自動化測試**。所有驗證都得由使用者在 DraftSight 裡實際跑指令。
- 最容易踩的三個雷：**檔案編碼**、**換行符與 git**、**DraftSight 與 AutoCAD 的 LISP 行為差異**。
  三者都在下面有專章。

日常工作規範另見 repo 根目錄的 `CLAUDE.md`（Claude Code 會自動載入）。

## 2. 環境與啟動

### 2.1 DraftSight 設定

- **Support Files Search Path** 需包含 `C:\DESIGNER6_DS` 與 `C:\POWPARTS_DS`
- **選單載入**：`CUSTOMIZE` → 載入 `C:\DESIGNER6_DS\Powsoft_Light.xml`
  （目前仍需手動載入，自動化列在待辦 §8）
- **自動載入**：DraftSight 啟動時執行內建 `start.lsp`，帶起 `startup.lsp`

### 2.2 啟動鏈

```
DraftSight 啟動
  → start.lsp（DraftSight 內建）
    → startup.lsp（C:\DESIGNER6_DS，11 行）
      → (load "command")   → COMMAND.lsp（832 行，所有 c: 指令的進入點）
      → (load "quickey")   → QUICKEY.lsp
      → (c:autoload)
          → (load "designer") → designer.lsp（5 行，只是轉接）
              → (load "PUB-LISP")
              → (load "config") → config.lsp（167 行）
                  → 讀 config.doc（英文 key、cp950）
                  → 設定 POWDESIGN_path、POWERPARTS_PATH 等全域路徑變數
          → (loaddesigner) → SYSTEM.lsp
              → get_layerdef / get_ltypedef / get_bomdef / get_bomlistdef
                 ← 目前一律回傳程式內建預設值（繞過 system.ini 讀取問題）
          → 若存在 campro.lsp 則載入（ERP 連結模組，選配）
```

> **已知小瑕疵**：`startup.lsp` 裡 `(load "command")` / `(load "quickey")` / `(c:autoload)`
> 各出現兩次（重複貼上）。目前不影響運作（`c:autoload` 內有 `POWDESIGN_path` 是否已設的守衛），
> 但會讓啟動多跑一次載入。整理時可一併移除。

## 3. 編碼規範（最重要的一章）

### 3.1 規則

| 類型 | 必須編碼 | 理由 |
|------|---------|------|
| `.lsp` | **UTF-8**（無 BOM） | DraftSight 2025 可正確讀取 |
| `.dcl` | **cp950 / Big5** | DraftSight 不支援 UTF-8 DCL，`load_dialog` 回傳 -1 |
| `.ini` `.doc` `.dat` `.txt` | **cp950 / Big5** | DraftSight 的 `open`/`read-line` 以 cp950 讀檔，UTF-8 會亂碼 |
| `.md` `.gitignore` `CLAUDE.md` | UTF-8 | 給人和工具讀 |

**同一個檔案內絕不可混用編碼。**

### 3.2 實測現況（2026-09-09）

DESIGNER6_DS，77 支 `.lsp`：

| 分類 | 數量 | 說明 |
|------|------|------|
| 純 UTF-8 | 64 | 正常 |
| 純 ASCII | 3 | 無中文，無所謂 |
| 純 Big5 | 10 | **尚未轉換**，見下表 |
| 混編碼 | 0 | 曾有 1 支，已於 c690ade 修正 |

尚未轉 UTF-8 的 10 支（多半是舊版備份或 PDM 殘留，目前不在載入鏈上，優先度低）：

```
COMMAND-.LSP        HP-K-old.LSP        HP-K.LSP
KB/COMMAND.LSP      KB/LOADSYS.LSP      KB/SETUP.LSP
PDMBOM3.LSP
PDMSERVER/Autocad/ACADDOC.OLD.LSP
PDMSERVER/Autocad/PUB-LISP.LSP
PDMSERVER/Autocad/WORDLIB1.LSP
```

POWPARTS_DS，114 支 `.lsp`：純 UTF-8 84 支、純 ASCII 30 支、**沒有殘留 Big5、沒有混編碼**。

`.dcl` 36 支全為 cp950（1 支純 ASCII）；`.ini` 8 支 cp950 / 6 支 ASCII。符合規範。

### 3.3 ⚠ 已造成的永久損傷：U+FFFD

早期一次 Big5→UTF-8 批次轉換使用了 `errors='replace'`，無法解碼的位元組被換成 U+FFFD（`�`）。
這些中文**已無法從 _DS 版本還原**：

| 檔案 | U+FFFD 個數 |
|------|------------|
| `MANABLK.lsp` | 4,712 |
| `COMMAND.lsp` | 3,295 |
| `SCRWLINE.lsp` | 2,103 |
| `TRAP_DIR.lsp` | 1,295 |
| `AUXEDIT2.lsp` | 529 |
| `ermsg.lsp` | 19 |
| **合計** | **11,953** |

POWPARTS_DS 完全沒有這個問題（0 個）。

**還原可行性（實測）**：這 6 支在 `C:\DESIGNER6` 都有原檔，但其中 5 支**原檔本身就不是合法的 cp950**
（只有 `COMMAND.lsp` 的原檔可以乾淨解碼為 cp950）。也就是說原始碼裡本來就混有非 Big5 的位元組，
不是單純換個轉換參數就能救。要修復需要逐檔人工比對，並非批次作業。

> **規則：不要再對 `.lsp` 跑批次編碼轉換。** 再跑一次只會製造更多 U+FFFD。
> 個別檔案需要修時，逐檔處理並在轉換時用 `errors='strict'`，失敗就停下來人工看。

### 3.4 動手前的檢查指令

```bash
# 驗 UTF-8
python3 -c "open('SHSCAL.lsp','rb').read().decode('utf-8'); print('UTF-8 OK')"
# 驗 cp950
python3 -c "open('shscal.ini','rb').read().decode('cp950'); print('cp950 OK')"
# 找出檔案裡非 UTF-8 的行號（用來抓混編碼）
python3 - <<'PY'
bad=[]
for i,l in enumerate(open('SHSCAL.lsp','rb').read().split(b'\n'),1):
    try: l.decode('utf-8')
    except UnicodeDecodeError: bad.append(i)
print('非 UTF-8 行:', bad or '無')
PY
```

## 4. 換行符與 git

repo 歷史是以 `core.autocrlf=true` 從 Windows 提交的：**版本庫存 LF、工作目錄存 CRLF**。

若在沒有這個設定的環境（例如 Linux、或透過網路磁碟掛載）操作 git，
`git status` 會把 **265 個檔案全部誤判為已修改**——那不是真的改動，是換行符解讀差異。

```bash
git config --get core.autocrlf    # 必須是 true
git config core.autocrlf true     # 不是就設定它（已於 2026-08-28 設好）
```

**症狀辨識**：`git status` 一次冒出上百個沒印象改過的檔案 → 先查這一項，不要照單全收去 commit。
一旦把 CRLF 提交進版本庫，之後所有人的 diff 都會爛掉。

### git 鎖檔陷阱

透過網路磁碟或受限掛載操作 git 時，`.git/index.lock`、`.git/HEAD.lock`、`.git/objects/tmp_obj_*`
可能因為無刪除權限而殘留，卡住後續所有 git 指令（`fatal: Unable to create index.lock: File exists`）。

```bash
rm -f .git/index.lock .git/HEAD.lock .git/objects/maintenance.lock
find .git/objects -name "tmp_obj_*" -delete
```

## 5. DraftSight 與 AutoCAD 的 LISP 行為差異

這是移植過程中最花時間的部分。以下每一條都是實際踩過的坑。

### 5.1 `load_dialog` 需要副檔名

AutoCAD 的 `(load_dialog "shscal")` 會自動補 `.dcl`，DraftSight 不會，會回傳 -1。

**修法**：`PUB-LISP.lsp` 的 `actdcl` 一律補副檔名 → `(load_dialog (strcat filename ".dcl"))`。已修。

### 5.2 `read-line` 不吐檔尾空行 ［推論，未實機查核］

**症狀**：`shscal.ini` 最後一段（`**凱柏圖框`）的最後一筆 `ASMA3` 在圖紙尺寸清單裡消失，
但非最後一段（`**凱柏零件圖框`）的 `A4` 正常。

**成因**：`SHSCAL.lsp` 的 `read_autoshscal_data` 原本把每段讀到的列一路 `cons` 進 `rdlist`，
再用 `(reverse (cdr rdlist))` 取出——那個 `cdr` 是**刻意**用來丟掉「段尾空白行」產生的 nil。
整個解析因此相依於「每段後面都有一行空白行」。檔案最後一段的空白行位在 EOF 前，
AutoCAD 的 `read-line` 會先回 `""` 再回 `nil`，DraftSight 推測是直接回 `nil`，
`rdlist` 的頭就變成最後一筆資料而被 `cdr` 丟掉。

**修法**（commit 52f6a64）：改成只收集以 `(` 開頭的有效資料列，直接用 `(cons nn (reverse rdlist))` 組裝，
不再依賴空白行、也不再用 `cdr` 丟東西。這個修法不管 `read-line` 的實際行為如何都正確。

**驗證推論的方法**（尚未執行）：在 DraftSight 命令列跑

```lisp
(setq f (open "C:\\DESIGNER6_DS\\shscal.ini" "r") n 0)(while (read-line f)(setq n (1+ n)))(close f)(princ n)
```

AutoCAD 應為 33。DraftSight 若回 32，即證實 `read-line` 不吐檔尾空行。

> **通用教訓**：原始碼裡任何「靠空白行、檔尾格式、行數當 sentinel」的寫法，在移植版都是高風險。
> 看到 `(cdr rdlist)`、`(reverse (cdr ...))` 這類寫法要優先懷疑。

### 5.3 `attdia 0` 無效

AutoCAD 的 `attdia 0` 讓 `INSERT` 改在命令列詢問屬性，可以用 `repeat n (command "")` 跳過。
DraftSight 的 `attdia 0` **完全無效**，插入含屬性的 block 時強制彈出對話框。

**影響**：`auto_insert_attsheet` 插入 `*tzt.dwg` 的流程。目前尚未有好解法，見 §7.1。

### 5.4 `entnext` / `entget` 限制

在某些情況（特別是 `command` 執行後），`entlast` 取得的 entity name 可能失效。
必須在 `command` **執行完成後立即**取得，不能跨函式傳遞。

### 5.5 動態作用域行為不同

`input_attedata` 從 `ATOshscal` 呼叫時，讀不到 `ATOshscal` 的區域變數（`?scl`、`sfilename` 等）。

**修法**：呼叫前把需要的值存成全域（命名慣例 `&&vctr`、`&&scl`、`&&sfilename`…），
並把 `attdata_list` 從 `ATOshscal` 的區域變數列表移除讓它變全域。已修。

### 5.6 中文 key 讀取問題

`system.ini` / `shscal.ini` 原本用中文當 key（`圖層定義`、`圖框日期型式`…），DraftSight 下讀取有問題。
已全面改為英文 key，並同步更新 17 支讀取這些 ini 的 LSP。對照表見 §10。

## 7. 已知問題

### 7.1 `autoSHSCAL` 屬性寫入需按兩次對話框（最高優先）

**現況**

- ✅ 「圖框屬性」對話框（`input_attedata`）可正常顯示與填寫
- ✅ `chg_sheetatt` 本身可正確寫入屬性（手動測試確認）
- ✅ `attdata_list` 資料正確（已改為全域變數）
- ⚠ 插入 `*tzt.dwg` 時 DraftSight 強制彈出屬性對話框，27 個屬性要逐一確認
- ⚠ `chg_sheetatt` 覆寫尚未完全驗證（插入流程還在調整）

**目前的權宜寫法**

```lisp
;; auto_insert_attsheet 中的關鍵段落
(command "insert" sfilename vctr ?scl ?scl "0")              ; 插入外框（無屬性）
(setvar "attdia" 1)
(command "insert" (strcat sfilename "tzt") vctr ?scl ?scl "0") ; 讓 DraftSight 彈對話框
(setq tzt_ent (entlast))
;; ... MOVE 圖框 ...
(if attdata_list (chg_sheetatt tzt_ent attdata_list))        ; 用「圖框屬性」對話框的值覆寫
```

**問題**：使用者要按兩次（DraftSight 屬性對話框 + 自家「圖框屬性」對話框），體驗差。

**理想解法**：讓使用者只填「圖框屬性」對話框後自動寫入。需要找到讓 DraftSight `INSERT`
跳過屬性對話框的方法。可探索方向：

- 改用 `entmake` 直接建構 INSERT + ATTRIB 實體，完全繞開 `command "insert"`
- 或先插入無屬性版本的 block，再用 `entmake` 補 ATTRIB
- ［未查核］DraftSight 是否有等同 `ATTREQ`/`ATTDIA` 的其他系統變數

### 7.2 括號不平衡的檔案

位元組層級掃描偵測到以下 `.lsp` 括號不平衡（`depth` 為正表示多了左括號）：

| 檔案 | depth | 備註 |
|------|-------|------|
| `TRAP_DIR.lsp` | +10 | 同時含 1,295 個 U+FFFD |
| `SCRWLINE.lsp` | +6 | 同時含 2,103 個 U+FFFD |
| `MANABLK.lsp` | −2 | 同時含 4,712 個 U+FFFD |
| `AUXEDIT2.lsp` | −1 | 同時含 529 個 U+FFFD |
| `LAYER.lsp` | +1 | |
| `FIELDSET.lsp` | −1 | |
| `HP-K.LSP` | −1 | Big5 檔，掃描結果不可靠（見下） |

**注意**：Big5 檔的第二位元組可能剛好是 `(` `)` `"` `\`，所以位元組層級的括號掃描
**只對 UTF-8 檔有效**，對 Big5 檔的結果不能採信。上表除 `HP-K.LSP` 外都是 UTF-8 檔。

前四支的不平衡很可能就是 U+FFFD 損毀造成的——原本被吃掉的位元組裡含有括號。
修復這些檔案等同於修復 §3.3 的損傷，需人工逐檔比對原版。

### 9.2 commit 慣例

沿用現有風格：`fix:` / `chore:` / `docs:` 前綴 + 中文說明。
內文寫「為什麼」而不只是「改了什麼」——這個專案的多數 bug 成因都不直觀，
下一個人（或下一個 session）需要的是推論過程。

### 9.3 push

執行 Claude 的環境**沒有 GitHub 憑證**，`git push` 會失敗。
一律由使用者在自己的 Windows 終端機執行 `git push origin main`。
Claude 完成 commit 後應主動告知還有幾個 commit 待推送。

### 9.4 修改 LISP 的固定流程

1. 先看原版 `C:\DESIGNER6` 對照
2. 確認目標檔的編碼（§3.4）
3. 用指令或腳本就地修改，不要憑工具輸出重打整份檔案
4. 驗證括號平衡（僅對 UTF-8 檔有效）
5. 請使用者在 DraftSight 實測，通過後才 commit

### 10.4 `shscal.ini` 格式

```
DATE_FORMAT=1                    ← 原「圖框日期型式」
POWERPDM_FRAME_MAP=(...)         ← 原「POWERPDM圖框屬性與CAD圖框對應」
ALL_SHEET_SCALE_TAG="SCALE"

**凱柏零件圖框                    ← ** 開頭 = 段名，即「圖紙型式」下拉選項
("A1" "A1" "C:\\DESIGNER6_DS\\SHEET\\A1" (786 491) ((屬性定義...)) "27" "SCALE")
("A2" ...) ("A3" ...) ("A4" ...)

**凱柏圖框
("ASMA1" ...) ("ASMA2" ...) ("ASMA3" ...)
```

每列欄位依序為：圖紙名稱、圖紙尺寸、圖檔路徑、`(空白區寬 高)`、屬性定義串列、屬性總數、比例屬性標籤。
特別識別碼：`S`=比例、`D`=日期、`Q`=數量、`F`=檔名、`T`=圖紙。
