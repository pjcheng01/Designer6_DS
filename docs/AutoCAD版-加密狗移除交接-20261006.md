## 0. 先看這一段：最大的坑

**移除加密狗時最容易出事的不是「漏刪」，是「刪過頭」。**

加密狗的外殼長這樣（`C:\DESIGNER6\AUX-QURY.lsp:553`，`c:e-len`）：

```lisp
(defun c:e-len(/ ent sp ep d in dtxt intxt word)
 (setvar "cmdecho" 0)
   (if (and (= jin "#$%")(= #### 85))(setq FFF t))(WHILE (/= FFF nil)(setq ppss sspp)
 (prompt "\n======= 選擇一條直線 … =======")
 (setq ent (entget (car (entsel "\n選擇欲計算的直線: ")))
       …
       d (+ (distance sp ep) ppss)        ; ← 這裡用到 ppss
       …)
 (SETQ FFF nil))
 (setvar "cmdecho" 1)
)
```

整個函式本體被包在 `(WHILE (/= FFF nil) … (SETQ FFF nil))` 裡——授權通過才跑一次。

**注意 `(setq ppss sspp)` 寫在 WHILE 的開頭。** 把外殼整段刪掉，`ppss` 就變成
未繫結，而算式裡還留著 `(+ (distance sp ep) ppss)` → `(+ 數字 nil)` → 指令中斷。

### 這在 DraftSight 版真的發生過

移植時整段換成一行註解，結果：

- `&e-len`（線段公英制長度）選完線段後直接 `*Cancel*`
- `&pul` `&pur` `&pdl` `&pdr`（旋轉投影線）四支**一按就中斷**，而且當時沒人發現
- `SLOT1/2/4/5`（`DRAWMECH.lsp`）同樣中斷

症狀很有誤導性：錯誤發生在 `entsel` **之後**的同一個 `setq`，所以畫面會先出現
「找到 1」才中斷，看起來像選取有問題。

### `ppss` 永遠是 0，直接從算式拿掉

三個獨立證據：

1. `SYSTEM.lsp:245`（已註解）的 `(setq sspp 0)`，而 `ppss` 來自 `(setq ppss sspp)`
2. 檢查式是 `(= #### 85)` 配 `(setq #### (+ sspp 85))`——要成立，`sspp` **必須**是 0
3. 原作者自己也這樣認定：`AUXDRAW1.lsp:128`（原版行號）寫了
   `(if (= ppss nil) (progn (setq ppss_v ppss)(setq ppss 0)))`

**所以 `(+ x ppss)` 改成 `x` 就好，不要把加密狗殘渣補回去。**

> **通用教訓**：移除保護機制時，要區分「**檢查邏輯**」與「**被檢查邏輯順便
> 初始化的變數**」。前者可以整段刪，後者刪掉就變未繫結。
> 排查方式是掃「讀」與「寫」兩份清單，找出**只有讀、沒有寫**的變數。

## 2. 建議的作業順序

### 步驟 0：先備份，再確認現況

```
1. 把 C:\DESIGNER6 與 C:\POWPARTS 完整複製一份當對照組（之後每一步都要能 diff）
2. 建 git repo 納管，第一個 commit 是「未修改的原版」
3. 在 AutoCAD 裡跑幾個指令，記錄「修改前」的行為當基準
```

**強烈建議納入版控。** DraftSight 版整個移植過程的除錯效率，很大一部分來自
「隨時能 diff 原版」。沒有版控的話，改壞了很難知道是哪一步。

### 步驟 1：確認 `loadsys` 到底有沒有被載入

在 AutoCAD 裡：

```lisp
(princ jin)        ; 應該印出 "#$%"，印出 nil 代表沒載到
(princ ####)       ; 應該印出 85
(princ sspp)       ; 應該印出 0
```

結果決定後面怎麼做：

- **都有值** → 第二層在運作，照步驟 2~4 做
- **都是 nil** → 第二、三層其實一直是「檢查失敗」狀態。那麼**那 334 個 WHILE
  外殼裡的程式碼從來沒有執行過**，這是個更大的發現，要先回頭確認那些功能
  現在到底能不能用

### 步驟 2：先拆第三層（334 處 WHILE 外殼）

這是工作量最大的一塊，但形狀固定，可以半自動處理。

**每一處的改法**：

```lisp
;; 改前
   (if (and (= jin "#$%")(= #### 85))(setq FFF t))(WHILE (/= FFF nil)(setq ppss sspp)
   …本體…
 (SETQ FFF nil))

;; 改後
   …本體…
```

也就是：刪掉開頭那一行、刪掉結尾的 `(SETQ FFF nil))`，**並且把本體少掉的一層
括號補平**。

⚠ **刪完立刻做兩件事**：

1. **掃 `ppss`。** 每刪一個外殼，就檢查該函式body裡有沒有讀 `ppss`。
   有的話把 `(+ x ppss)` 改成 `x`（理由見 §0）。
   全庫 `ppss` 出現 161 次，`AUXDRAW1.lsp` 就佔 37 次。
2. **驗括號平衡。** 刪掉 WHILE 等於少一層括號，很容易漏補。

> DraftSight 版當初是把整段換成一行註解
> `;; DraftSight: 移除加密狗 WHILE 迴圈`，保留括號結構。
> **那是比較保守的做法，建議照抄**——改動小、好 diff，而且不會動到縮排。

### 步驟 3：拆第二層

`C:\POWPARTS\LOADSYS.LSP:96-110` 的 `(setq jin … #### … sspp 0)` 可以直接刪，
但**要等第三層拆乾淨之後**——這兩層是配套的，先拆第二層會讓所有功能立刻失效。

### 步驟 4：拆第一層與周邊檔案

- `creat_keypro_data`（兩支 `LOADSYS.LSP`）
- `CONFIG.lsp:188` / `CONFIG.LSP:101` 的 `(load "loadsys")`

- 根目錄的 `FINDKEY.EXE`、`安裝Key程式\` 整個資料夾

### 步驟 5：DraftSight 版漏清的地方——你不要重蹈

⚠ **這一節講的是「DS 版漏掉哪些」，不是原版的狀態。**
原版還沒清過，所有東西都是完整的。

DS 版拆完之後掃到、但判定無害而沒有動的三類：

## 3. 驗證方法

### 3.1 必測的「容易被忽略」清單

這些是 DraftSight 版踩過、**拆完外殼後最可能壞掉**的：

| 指令 | 檔案 | 為什麼危險 |
|------|------|-----------|
| `&e-len` 線段公英制長度 | `AUX-QURY.lsp` | 算式用 `ppss`，DS 版實際中斷過 |
| `&pul` `&pur` `&pdl` `&pdr` 旋轉投影線 | `PROJLINE.lsp` | 同上，而且**當時沒人發現**，是掃出來的 |
| `SLOT1/2/4/5` | `DRAWMECH.lsp` | 沒有選單分派，只能在指令列直接打 |
| `c:cen1` | `AUXDRAW1.lsp` | 第 128 行本來就有 nil 防護，**不要動** |

> `SLOT1/2/4/5` 沒有任何分派點也不在選單上，但它們是 `c:` 函式——
> `drawmech` 被 `&lc`（軸銑雙邊，在 `Usermenu.mnu`）載入之後，
> 在指令列直接打 `SLOT5` 就會執行。

### 3.2 掃描腳本

拆完之後，用「只有讀、沒有寫」的方法找遺漏：

```bash
# 列出所有「讀」ppss 的位置（排除 (setq ppss …) 這種寫入）
grep -rn 'ppss' C:/DESIGNER6 C:/POWPARTS --include=*.lsp --include=*.LSP \
  | grep -v 'setq ppss'
```

剩下的每一個都要確認：該處的函式是否已經沒有 `(setq ppss sspp)` 了。
原版全庫 `(setq ppss sspp)` 共 **138 處**、讀取 `ppss` 共 161 處。

同樣的方法套用在 `FFF`、`jin`、`####`、`sspp`。

### 3.3 括號平衡

拆 WHILE 外殼最容易漏補括號。用**會跳過字串與註解**的掃描器，
單純數 `(` `)` 會把字串裡的括號也算進去：

```awk
# balance.awk
{
  line = $0; n = length(line)
  for (i = 1; i <= n; i++) {
    ch = substr(line, i, 1)
    if (instr) { if (ch == "\\") { i++ } else if (ch == "\"") { instr = 0 } }
    else {
      if (ch == ";") break
      else if (ch == "\"") instr = 1
      else if (ch == "(") depth++
      else if (ch == ")") depth--
    }
    if (depth < 0) { print "  第 " NR " 行出現多餘的 )"; depth = 0 }
  }
}
END { print "  最終深度 = " depth }
```

⚠ 它**不認得 `;| … |;` 區塊註解**，那種檔案要人工看。
另外原版是 **Big5**，第二位元組可能正好是 `(` `)` `"` `\`——
**位元組層級的掃描對 Big5 檔不可靠**，要先確認工具是以字元而非位元組處理。

## 4. 原版的編碼與換行（動手前必讀）

`C:\DESIGNER6` / `C:\POWPARTS` 的 `.lsp` 是 **Big5（cp950）**，不是 UTF-8。

- 寫中文註解前先確認該檔目前的編碼，**絕不可在單一檔案內混用編碼**
- **不要整批重跑編碼轉換**。DraftSight 移植早期一次用 `errors='replace'` 的
  批次轉換，在 6 個檔案裡留下約 11,953 個 U+FFFD，中文永久損毀
- AutoCAD 版**沒有理由轉 UTF-8**，維持 Big5 就好

驗編碼：

```bash
python -c "d=open('AUXDIM.lsp','rb').read(); d.decode('cp950'); print('cp950 OK')"
```
