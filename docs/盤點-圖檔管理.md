## 0. 三分鐘版本

這組功能由**兩支 exe** 撐著，兩支都因為缺 BDE 而無法執行。但實際受影響的
使用者入口比預期少得多——**核心的兩個指令根本不在選單上**。

|  | 數量 |
|---|---|
| 相關程式碼 | 約 **217 行**（集中在 `MANAPART.lsp`） |
| 壞掉且在選單上的 | **0 個** |
| 壞掉但只能打指令的 | **2 個**（`&opendwg`、`&insdwg`） |
| 部分壞掉（選單上） | **1 個**（`&pdmwblk` 建立內部 BLOCK） |
| 完全正常 | **4 個** |

**替代路徑很明確**，而且專案裡已經有兩個驗證過的現成範本。

## 1. 這組功能的實際結構

```
【寫入路徑】
  &pdmwblk（選單：建立內部 BLOCK）
    → wblock 存出圖檔                      ← 純 LISP，正常
    → 問「是否建立物料資訊?」
    → append_to_dwg_db  DCL 對話框          ← 純 LISP，正常
    → 寫出 data.txt（一行）                 ← 純 LISP，正常
    → trans_data_todwg_db
        → 寫 c:\bompath.txt                ← UAC 問題（已有解法）
        → change.exe  把 data.txt 併入 dwg.db   ← ✗ 缺 BDE

【讀取路徑】
  &opendwg / &insdwg（不在選單，只能打指令）
    → 寫 c:\bompath.txt                    ← UAC 問題
    → manadwg.exe  瀏覽 dwg.db 選圖         ← ✗ 缺 BDE
    → 讀回 c:\part.txt 取得選中的檔名        ← 依賴上一步
    → open / insert                        ← 純 LISP，正常
```

**只有中間那一段是壞的**，兩端都是好的純 LISP。

## 3. 資料檔

| 檔案 | 格式 | 大小 | 誰讀寫 |
|------|------|------|--------|
| `dwg.db` | **Paradox（BDE）** 二進位 | 61 KB (2009) | 只有 `manadwg.exe` / `change.exe` |
| `dwgdata.txt` | 純文字，`欄位代號;顯示名稱` | 175 bytes | **LISP 讀寫**（`c:fieldset` 維護） |
| `data.txt` | 純文字，`;` 分隔 | 2.8 KB | **兩個不相干的寫入者，見下** |
| `c:\bompath.txt` | 單行路徑 | — | LISP 寫、exe 讀 |
| `c:\part.txt` | 單行路徑 | — | exe 寫、LISP 讀 |

`dwgdata.txt` 的內容長這樣：

```
A_01;料號
A_02;品名
A_03;材質
A_04;#圖號
...
```

**與 `title.txt`、`partdata.txt` 是同一種模式**——這很重要，見 §4。

### ⚠ `data.txt` 有兩個寫入者，而且互相覆蓋

| 寫入者 | 內容 | 有人讀嗎 |
|--------|------|----------|
| `BOM.lsp:144`（拆圖 `exeout`） | 每個拆出的零件一行，作為「manadwg 轉檔檔」 | **沒有**——拆圖不呼叫 `trans_data_todwg_db` |
| `MANAPART.lsp:398`（`append_to_dwg_db_ok`） | **只有一行**，接著呼叫 `change.exe` | `change.exe`（已壞） |

所以現況是：拆圖辛苦寫出整份清單，下次執行「建立內部 BLOCK」就被一行蓋掉，
而且兩邊都沒有真正進到 `dwg.db`。工作目錄裡那個 2.8 KB 的 `data.txt`
（2026-09-11 13:53）就是拆圖測試留下來的。

這是原版就有的設計問題，不是移植造成的。

## 4. 替代路徑

### 4.1 專案裡已有兩個驗證過的範本

**範本一：`partdata.txt`（資訊點資料源）**

2026-09-10 已經做過一次完全相同性質的替換——「自動建立資訊點」原本連 CAMPRO
ERP 資料庫，改為直接讀 `partdata.txt`（cp950、分號分隔、CRLF、83,190 筆），
掃描 3~5 秒，使用者實測通過。

`dwg.db` 要換掉的話是同一件事，而且資料量小得多（61 KB vs partdata 的數 MB）。

**範本二：`userblkm` / `userblku`（自訂圖庫）**

這兩支是**純 LISP 的圖庫瀏覽器**——DCL 對話框 + 滑動預覽（`.sld`）+ 分類，
完全不需要外部程式，而且目前運作正常（本次瘦身期間才修好符號庫全系列）。

`manadwg.exe` 要做的事（瀏覽圖庫、預覽、選一個回傳檔名）**它已經在做了**。

另外 `c:bomlist` 用的 `free_list_designer` 是純 LISP 的清單對話框，
適合用來做「表格式瀏覽」。

### 4.2 建議做法

| 步驟 | 做法 | 難度 |
|------|------|------|
| 1 | 把 `dwg.db` 匯出成 `dwglib.txt`（`;` 分隔純文字） | **要在有 BDE 的環境做一次**，或另寫 Paradox 解析器 |
| 2 | `append_to_dwg_db_ok` 改為**附加一行到 `dwglib.txt`**，移除 `trans_data_todwg_db` 與 `change.exe` | 低——只是把 `"w"` 改 `"a"`、拿掉 startapp |
| 3 | `c:opendwg` / `c:insdwg` 改用 DCL 清單對話框讀 `dwglib.txt` | 中——可大量沿用 `userblkm` 或 `free_list_designer` |
| 4 | 移除 `manadwg.exe`、`change.exe`、`dwg.db`、`c:\bompath.txt` 與 `c:\part.txt` 的所有依賴 | 低 |

**步驟 1 是唯一的真正障礙。** `dwg.db` 是 Paradox 格式（檔頭 `E8 03 00 10 02 04 2F`），
BDE 已經裝不起來，所以要嘛：

- 找一台還有 BDE 的舊機器匯出一次，或
- 用 Python 的 `pypxlib` 之類的函式庫直接解析（`dwg.db` 只有 61 KB，欄位定義
  又在 `dwgdata.txt` 裡，可行性高），或
- **放棄舊資料重新建立**——如果 2009 年的圖庫內容已經沒有參考價值

第三個選項要由您判斷：`dwg.db` 是 2009 年的檔案，**17 年沒有更新過**。

## 5. 建議的優先序

考量到「壞掉且在選單上的功能是 0 個」，這組的急迫性**低於**目前的瘦身待辦。

| 優先 | 項目 | 理由 |
|------|------|------|
| 低 | 修 `&opendwg` / `&insdwg` | 不在選單上，17 年的資料庫，先確認還有沒有人用 |
| **中** | 修 `&pdmwblk` 的物料資訊寫入 | **這個在選單上**，使用者按了「是」卻沒有效果，屬於無聲失敗 |
| 中 | 清掉 `data.txt` 的雙寫入者衝突 | 現況是兩邊都白做工 |
| 低 | 移除 `manadwg1.exe`、`Seldir.exe`、`copyfile.exe`、`U.exe`、`DSelFile.exe` | 這五支**完全沒有任何引用**，純殘留 |

### 使用者的回答（2026-09-11）

1. **`dwg.db` 的 2009 年資料**：沒有保留價值 → **匯出 Paradox 的障礙直接消失**
2. **`&opendwg` / `&insdwg`**：沒在用 → **可以直接移除**
3. **「建立物料資訊」**：沒用過，但希望改成**從 `partdata.txt` 自動帶入**

## 6. 評估：「建立物料資訊」改讀 `partdata.txt`

**結論：可行，而且比預期簡單很多。** 三個關鍵元件都已經存在。

### 6.1 對應表已經在設定檔裡

`SYSTEM.ini` 的 `PART_DEF` 有**第四欄**，正是 `dwgdata.txt` 的 `A_xx` 代號：

```
("品名"     "DWGNAME"  "TAG3"  "A_02")
("材質"     "MATERIAL" "TAG4"  "A_10")
("#圖號"    "DWGNO"    "TAG5"  "A_04")
("英文品名" ""         "TAG9"  "A_08")
("規格"     ""         "TAG10" "A_06")
("表面處理" "SURFACE"  "TAG8"  "A_09")
...
```

13 筆裡有 11 筆能正確對到 `dwgdata.txt`，只有「備註→A_11」與「廠牌→A_12」
是命名上的差異（`dwgdata.txt` 寫的是「說明」與「未定」），不影響結構。

**意義**：轉換規則是資料驅動的，不必在程式裡寫死欄位對照。
使用者日後用 `c:fieldset` 調整欄位，對應會自動跟著走。

### 6.2 讀取函式已經存在且實測通過

`MANAPART.lsp:2219` 的 `read_partdata_file` 是 2026-09-10 為「自動建立資訊點」
寫的，功能正好是「給一串料號，掃 `partdata.txt` 撈出對應資料列」。
單一料號就是傳一個元素的串列，**不必新寫**。

搭配的 `first_field`（2191）也是現成的。

### 6.3 能填幾欄

`partdata.txt` 的七個欄位對到 `dwgdata.txt`：

| partdata | TAG | → | dwgdata | 欄位名 |
|----------|-----|---|---------|--------|
| 第 1 欄 | 料號 | → | `A_01` | 料號 |
| 第 2 欄 | TAG3 | → | `A_02` | 品名 |
| 第 3 欄 | TAG9 | → | `A_08` | 英文品名 |
| 第 4 欄 | TAG10 | → | `A_06` | 規格 |
| 第 5 欄 | TAG4 | → | `A_10` | 材質 |
| 第 6 欄 | TAG8 | → | `A_09` | 表面處理 |
| 第 7 欄 | TAG5 | → | `A_04` | #圖號 |

**七欄可自動填入。** 填不到的是 `A_03`(機種)、`A_05`(製圖)、`A_07`(數量)、
`A_11`(說明)，以及 `A_12`~`A_15`（未定義）。

這**不是限制而是正確行為**——那四個欄位本來就是「每次使用都不同」的值
（誰畫的、這次用幾個、哪個機種、備註），不屬於料號主檔，
留白讓使用者自己填才對。

### 6.4 實作範圍

| 動作 | 位置 | 難度 |
|------|------|------|
| 對話框開啟時以料號查 `partdata.txt`，預先填入七欄 | `append_to_dwg_db`（`MANAPART.lsp:340`） | 低 |
| 寫入端改為附加一行到純文字圖庫檔，取代 `change.exe` | `append_to_dwg_db_ok`（388） | 低 |
| 移除 `trans_data_todwg_db` | 411，共 9 行 | 低 |
| 移除 `c:opendwg`、`c:insdwg` | 426、502，共 124 行 | 低 |

**料號從哪來**：`c:pdmwblk` 用 `getfiled` 讓使用者選存檔檔名，取其主檔名即可
——這與現行慣例一致（拆圖的 `out_dwgname` 也是由圖層名／料號而來）。

### 6.5 唯一要留意的

`read_partdata_file` 會**完整掃過 83,190 筆（4.7 MB）**才回傳。
「自動建立資訊點」實測 3~5 秒可接受，因為那是一次撈整張圖的料號；
但「建立內部 BLOCK」每次只查一筆，卻要付同樣的掃描成本。

初期直接沿用即可（正確優先）。若實際使用覺得慢，再考慮建索引或改成
「只讀到命中就中止」——後者很簡單，因為料號是第一欄且唯一。

### 6.6 連帶可以移除的東西

有了 1 與 2 的答案，這些全部可以清掉：

| 項目 | 說明 |
|------|------|
| `manadwg.exe`、`manadwg1.exe` | 只服務 `c:opendwg` / `c:insdwg` |
| `change.exe` | 只服務 `trans_data_todwg_db` |
| `dwg.db` | 2009 年資料，使用者確認無保留價值 |
| `c:ompath.txt`、`c:\part.txt` 的依賴 | 這組是最後的使用者，清掉後全專案不再依賴 C 槽根目錄 |
| `Seldir.exe`、`copyfile.exe`、`U.exe`、`DSelFile.exe` | 本來就完全沒有引用 |

**清完之後，全專案唯一還會啟動的外部程式只剩 `selfile.exe`**
（28 KB、無 Borland 相依，四處呼叫，尚未實測）。
